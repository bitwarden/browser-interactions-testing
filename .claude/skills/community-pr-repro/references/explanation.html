community-pr-repro

Turns a community autofill fix into proof: the bug reproduces on main, a BIT test catches it, and the PR's build makes that test pass.

One run = one PR or issue. With an issue only, it stops at the failing baseline. Start with a fill/no-fill bug such as clients#23906.

Workflow

1
Read the PR or issue, write the repro briefMap the bug to a BIT TestNames key and its run command. Stop if no spec asserts it.
Checkpoint: brief
↓
2
Start the environment, build maindocker compose up, start:test-site, build:extension from clients@main.
↓
3
Find or add the pattern page, reproduce by handLook at the reported live site first (observe only, video). Reuse an existing test-the-web page if it shows the bug, else add one in test-site/client/docs/forms/. Reproduce with Playwright MCP.
Checkpoint: bug reproduced
↓
4
Add the BIT entry, confirm it fails on mainAppend to testPages + pageCiphers, skip specs that don't apply, seed, run the brief's command with START_FROM_TEST_URL.
Checkpoint: failing for the right reason
↓
5
Build the PR, confirm it passes (skip without a PR)gh pr checkout in $BIT/clients, rebuild, rerun the same entry.
↓
6
Write the report, log learningsReport for the human reviewer; skip flag with ticket until merge; append to learnings.md.
Checkpoint: report

Inputs and outputs

Inputs Outputs
Community PR or bug report (issue) on bitwarden/clients repro/<id>/brief.md, report.md, and videos of the site, the manual repro, and the BIT runs on main and the PR
Tracker ticket, e.g. PM-45163 (in community PR titles) New or reused test-the-web pattern page
New or updated BIT testPages + pageCiphers entry, failing on main and passing on the PR

Key constraints

  • Do first-time BIT setup (npm run setup:all) before the run: Docker, certs, vault account, and a full clients install take longer than the session.
  • Fork PRs sit at action_required in build-browser.yml, so there is no artifact to download. Build the PR locally.
  • MV3 needs a real display: headless runs are broken. Run headed, with one Playwright worker.
  • The MCP config records every Playwright context start-to-close. Do setup (navigate, unlock, verify selectors) in a throw-away session, close, delete repro/_pending-videos/*.webm, then relaunch for a tight recorded pass — otherwise the saved video bloats to minutes of fumbling.
  • The classifier blocks routing VAULT_PASSWORD into the Playwright MCP sandbox (filesystem reads, pipes, loopback servers all denied). Ask the user to unlock the popup interactively — the vault re-locks on every Playwright relaunch, so one unlock inside each recorded session is unavoidable.
  • Never use test.skip() in spec files. Known failures go in skipTests with a ticket.
  • START_FROM_TEST_URL must match the entry URL exactly, or the whole suite runs.
  • Don't change an existing test-the-web pattern's behavior. Add a new page.
  • For #23906, the extension must collect the form before Country rebuilds the State options. Put that sequence in the first input's preFillActions, or the test can pass on main and miss the bug.
  • #24710 (wrong cipher type in the inline menu) can't be asserted yet: shouldNotHaveInlineMenu only checks that no menu appears at all.
  • BIT's pretest deletes tests-out/videos. Copy each run's videos into repro/<id>/ before the next run.
  • A new BIT entry runs in every static spec. Skip the ones that don't apply, with reasons.
  • Out of scope: inline menu position bugs, batches of PRs, judging code quality, and benchmarking.
